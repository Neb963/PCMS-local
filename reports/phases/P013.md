## Objective

Prove persistent browser state and isolation across multiple real Chromium Persona processes.

## Implemented

- T013.1 — added a typed `ChromiumBrowserManager` that probes an explicitly configured Chromium-compatible executable, launches it directly without shell command concatenation, uses the P012-owned non-default Persona profile root, selects a dynamic DevTools port, discovers `DevToolsActivePort` from that profile, and verifies the reported browser WebSocket endpoint is loopback-only and matches the profile-scoped endpoint before returning a session.
- Browser launch arguments are fixed/typed. Arbitrary caller-provided Chromium switches are not accepted. The production default keeps Chromium's sandbox enabled; the real-browser CI path uses a narrowly named `disableSandboxForTesting` option because GitHub's Ubuntu runner cannot start Chrome for Testing's normal sandbox.
- Normal close now sends CDP `Browser.close` over the verified browser WebSocket and waits boundedly for the owned process to exit; only then does it fall back to SIGTERM/SIGKILL against the known child. This preserves profile-backed local storage while keeping process termination bounded.
- T013.2 — added a loopback fixture page exercised by real Chrome for Testing. It writes/reads a session-style cookie, `localStorage`, and IndexedDB through ordinary browser JavaScript, closes/reopens each Persona, and proves values persist for the same Persona while a second Persona begins empty and retains only its own values.
- T013.3 — added simultaneous real-browser acceptance. Two Personas run concurrently with distinct PIDs, profile roots, DevTools ports/origins/WebSocket endpoints and OPEN lifecycle state. Closing one leaves the other process and DevTools endpoint healthy.
- Added a dedicated `test:browser` suite and a required **Real Chromium Persona** GitHub Actions job. The job downloads exact Chrome for Testing 154.0.8037.92 from the official Chrome-for-Testing distribution URL and verifies archive SHA-256 `ff43322f335e436b2f4dcdfeeec5db032299e335a7e8c1c618b326e100ce8732` before execution. The Foundation aggregate now requires this browser job.

No crash/restart reconciliation, persisted runtime fingerprints, ambiguous existing-process attachment, active-Persona resource cap, routing, provider automation or MCP behavior was implemented. Those remain owned by P014/P015 and later phases.

## Deviations / ADRs

No architecture deviation and no new ADR.

GitHub-hosted Ubuntu prevented Chrome for Testing from starting its normal Linux sandbox. P013 therefore includes an explicit test-only launch option for `--no-sandbox`; it is disabled by default and is not a generic command-line escape hatch. This is CI environment accommodation, not a production sandbox policy change.

The original signal-only close path was replaced with the architecture-specified graceful `Browser.close` behavior after real-browser evidence showed localStorage loss. Signal escalation remains only a bounded fallback for the known child process.
