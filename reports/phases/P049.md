## Objective

Confirm the current Perchance surface still matches the adapter and verify one disposable real Deployer mutation before final release sign-off.

## Outcome summary

**A12-04: FAIL — blocked by the provider's own perimeter, not by PCMS.**
**A12-05: FAIL — not attempted; mutation preflight cannot be satisfied.**

The live Perchance web application's Cloudflare perimeter accepts document
 navigations from the PCMS protected Persona (real Mullvad egress, verified at
forwarder and browser level) but returns an unsolvable `403` managed-challenge
HTML page for **every POST to the provider's `/api/*` JSON surface** — the
exact surface the PerchanceProvider adapter (session identity probe, generator
inventory read, save/getGeneratorPageData) depends on. This was reproduced
from six Mullvad exits across Europe and the US and from the host's own
network, with a real headed Chromium, across ~4.5 hours. No document-level
challenge is offered on the API path, so there is no clearance a human (or
the operator) could complete; the operator independently confirmed some
Perchance/Mullvad combinations are "always" flagged without a solvable
challenge.

Per the operator instructions ("An unavailable or unverified live gate is not
PASS. Record the exact blocker truthfully"), the phase is recorded BLOCKED.
No release sign-off is claimed; M12 remains IN_PROGRESS; P049 remains the
sole active phase.

## Live Perchance observations (sanitized)

1. Document navigations from the protected Persona load the real
   application; fresh profiles matter (profiles that accumulated failed
   challenge state loop on subsequent loads; a fresh profile loads cleanly —
   the profile, not only the exit IP, carries perimeter reputation).
2. Headless Persona browsers are document-challenged far more aggressively
   than headed ones; all live acceptance used the visible headed Persona.
3. POSTs to `/api/*` are answered with `403` managed-challenge HTML on every
   tested Mullvad exit and from the host network; the API path never offers
   a document-level challenge, so no interactable challenge exists to solve
   (consistent with the operator's independent finding).
4. The adapter's fail-closed classification behaves exactly as modeled in
   deterministic CI when confronted with the live perimeter.
