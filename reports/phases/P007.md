## Objective

Run module backend code outside pcmsd behind bounded typed IPC and contain runtime loss.

## Implemented

- T007.1 — added a generic dedicated `module-runner` child lifecycle with exact package-root/backend entry selection, runtime-generation and startup-nonce handshake, one framed stdio RPC channel, bounded frame/outstanding-request/time limits, structured errors and graceful bounded stop behavior. The runner loads exactly one `createModule(context)` backend and never executes module code inside pcmsd.
- T007.2 — added a serialized module SDK boundary. Module context contains only frozen module identity metadata plus `sdk.call()`; Core exposes only explicitly registered semantic SDK handlers. Raw DB/database/SQLite/router/CDP/process/handle method surfaces are rejected, and unapproved semantic calls return `MODULE_SDK_METHOD_DENIED`.
- T007.3 — added deterministic process-fault integration coverage with real pcmsd and an unrelated module runtime. RPC timeout/backpressure, outbound oversize payload, module process crash and malicious oversized wire-frame faults remain isolated; outstanding crash/protocol requests fail structurally while pcmsd and the unrelated module continue responding.
- Hardened the frame decoder to accept multiple valid frames coalesced into one stdout chunk while retaining a per-frame memory bound, and made child close handling robust to startup/spawn failures.

No module package activation/update lifecycle, namespaced state migration, stale-generation fencing after activation changes, module UI or automatic restart policy was implemented.

## Deviations / ADRs

No architecture deviation and no new ADR.

The initial RPC encoding is four-byte length-prefixed JSON over inherited stdio as prescribed by architecture 06. The process boundary is explicitly lifecycle/crash isolation for operator-trusted same-user code, not an adversarial sandbox.

## Known issues / unknowns

- P007 does not persist module runtime registrations or generation state in SQLite; P008 owns module storage generations and stale-runtime fencing across update/disable transitions.
- P007 does not implement candidate package activation, capability-expansion approval, rollback, module UI or automatic restart policy; those remain owned by later M02 phases.
- Same-user module code can still use OS authority available to that user outside the supported PCMS SDK. This is the documented V1 trust model, not a sandbox claim.
