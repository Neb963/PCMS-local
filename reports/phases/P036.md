## Objective

Complete Refresher manual/scheduled/recent-visibility execution against the deterministic Perchance emulator, retain verified per-Generator history, preserve Core-owned uncertainty/claim semantics, and prove Refresher follows the ordinary independently updateable `.pcmsmod` lifecycle.

## Implemented

- T036.1 — added `src/refresher/execution.ts` with a bounded semantic Refresher execution service over stable Generator identity, the existing `RefresherAdmission`/ProviderGate, and the P034 refresh/listing contract. The service persists durable operation identity before dispatch and verifies the intended emulator refresh effect plus exact public listing state before marking the Core operation successful.
- T036.1 — manual refresh records verified history only after the provider effect is confirmed. A repeated completed operation/idempotency identity returns the existing verified result without a second mutation.
- T036.1 — scheduled execution consumes the existing durable scheduler identity and records its terminal operation. `RECENT_VISIBILITY` additionally requires a verified VISIBLE refresh effect and presence on the recognized recent surface; save acknowledgement alone is insufficient.
- T036.1 — added a bounded per-Generator `RefresherHistoryLedger` and serializable snapshot shape. History contains operation/claim identity, stable provider identity, mode, refresh token/sequence, effect state, recent rank when proven, and verification time; it contains no session material or credentials.
- T036.2 — an ambiguous mutation loss is recorded through `OperationCoordinator.recordExecutionLoss` as `UNCERTAIN`. The unresolved stable Generator claim remains blocking, so a second operation cannot dispatch against the same target.
- T036.2 — retrying the original durable operation identity performs read-first `OperationReconciler` verification under the shared ProviderGate. Exact emulator effect/public-state evidence resolves the original operation to `SUCCEEDED` and records history without another save; unknown/mismatching evidence remains unresolved.
- T036.3 — added a deterministic Refresher `.pcmsmod` fixture using the standard manifest/parser/ModuleManager/module-runner/SDK path. Lifecycle acceptance installs 1.0.0, retains module-owned verified-history/policy state through update to 1.1.0, fences the stale runtime, and rolls back to retained 1.0.0 state through a new runtime generation.
