## Objective

Encode the evidence-backed refresh mutation/effect and listing/recent observation behavior needed by Refresher before any scheduled automation, while failing closed on unrecognized provider semantics or shape drift.

## Implemented

- T034.1 — extended the Perchance emulator with an explicit refresh-effect state machine. A normal provider save containing a bounded paired `PCMS_MARKER_BOTH_V1` marker records a refresh effect as `PENDING`; it does not implicitly make the generator recent.
- T034.1 — added a deterministic `publishRefreshEffect(publicId)` fixture action that models the separate asynchronous transition from confirmed save to recent-page visibility.
- T034.1 — added separate emulator semantic surfaces for public/library listing, recently-updated observation, and refresh-effect observation. The public/library surface includes public generators independently of recent membership.
- T034.1 — added a `COMPATIBILITY_DRIFT` fault scenario and controllable recent-observation completeness.
- T034.2 — added `src/providers/perchance-refresh-contract.ts` with bounded semantic decoders for public/library listing, recent observation, and refresh-effect observation.
- T034.2 — exact fixture contract version and semantic identity are required. Unknown versions, malformed shapes, duplicate identities, contradictory recent counts, or a valid surface passed to the wrong semantic decoder normalize to `compatibility = UNKNOWN`.
- T034.2 — recent absence becomes credible only when the recent semantic contract is recognized and `complete = true`. A recognized incomplete observation may preserve positive items but cannot prove absence.
- T034.2 — refresh save confirmation remains separate from recent visibility: `PENDING` and `VISIBLE` are distinct normalized effect states and unknown effect shapes become `UNKNOWN`.
- T034.3 — added `docs/research/P034-REFRESH-EMULATOR-EVIDENCE.md`, recording the evidence boundary, retained predecessor provenance, explicit emulator-only assumptions, secret hygiene and live questions deferred to P049.

## Deviations / ADRs

No ADR change was required.

The emulator's `/__pcms_emulator__/observations/*` routes and `contractVersion: 1` envelopes are deliberately internal semantic fixtures, not asserted Perchance URLs or live wire formats. This avoids inventing a stable recent-page API where retained evidence does not establish one.

The refresh model uses the retained bounded paired marker semantics as evidence provenance, but P034 does not copy predecessor runtime code. A refresh is represented as an ordinary save/deploy plus a separately observable recent effect; no dedicated provider refresh endpoint was invented.

## Known issues / unknowns

- P034 does not establish the current Perchance recent-page DOM structure, a current recent-page API, or current live save-to-recent timing. Those remain live compatibility questions for P049.
- The deterministic marker-effect model does not establish operational safety for every live generator class, especially sensitive/server-plugin/collaboration cases.
- Public/library and recent surfaces remain separate by design; live extraction belongs inside provider compatibility logic once evidence exists.
- P034 contains no Refresher scheduling/cohort policy. P035 owns that work.
