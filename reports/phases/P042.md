## Objective

Restore optional closed-Persona profiles and Core state without synthesizing health or replaying mutations.

## Implemented

- T042.1 — added a separate bounded `pcms-profile-backup-v1` format for optional Persona Chromium profiles. Backup requires the Persona to be CLOSED/PRESENT with no live browser-runtime row, validates the durable ownership marker, rejects symlinks and unsupported filesystem entries, records per-file hashes/modes plus the exact observed Chromium version/platform/architecture, and only restores into an empty owned profile location. Compatibility is deliberately conservative: exact Chromium version, platform and architecture are required; incompatible backups are reported without writing profile state.
- T042.2 — added migration `0015-recovery-control` and durable `NORMAL` / `RECOVERY_HOLD` state. Core restore validates and stages the backup first, migrates only the staging database, restores compatible optional profiles, enters `RECOVERY_HOLD`, preserves the previous live root as a safety directory and atomically activates the staged root. Both scheduler wake/claim and `OperationCoordinator.authorizeDispatch` fail closed while recovery hold is active, so overdue schedules are not advanced or dispatched.
- T042.3 — added recovery assessment that distinguishes local availability from external reconciliation state. Persona profiles are reported `AVAILABLE`, `MISSING` or `UNSAFE`; referenced module packages are `AVAILABLE`, `MISSING` or `INVALID`; local state becomes `DEGRADED` when required local material is unavailable; provider-owned external state remains `UNKNOWN_RECONCILIATION_REQUIRED` rather than being synthesized healthy.
