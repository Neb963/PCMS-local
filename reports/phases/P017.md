## Objective

Add the distinct Chromium-compatible route forwarder contract required by architecture 04 while preserving the existing authenticated Firefox-compatible `prepare_exit` path.

## Implemented

- T017.1 — added distinct daemon commands `prepare_chromium_exit` and `release_chromium_exit` plus typed Core client methods. A Chromium lease is keyed by route ID, runtime lease ID and positive lease generation; route/lease/TTL inputs are bounded and validated before route side effects.
- T017.1 — introduced a separate `ChromiumExitForwarder` that terminates Chromium's no-auth local SOCKS5 greeting and independently opens the existing no-auth Mullvad relay hop. It does not reuse or weaken the authenticated Firefox `ExitForwarder`.
- T017.2 — bound each Chromium forwarder to IPv4 `127.0.0.1` on kernel-selected port 0, with bounded TTL (1–300 seconds), active timer expiry, explicit release and Router-owned cleanup. Expiry/release close the listener and active sockets.
- T017.2 — same lease/generation replay is idempotent and does not extend the original TTL; an active route lease cannot be silently replaced by another lease/generation or relay.
- T017.3 — added deterministic native tests for loopback binding, Chromium no-auth negotiation, upstream relay greeting, active expiry, explicit release, accepted-socket teardown, stale-generation release, takeover refusal, invalid lease inputs and post-expiry route cleanup.
- T017.3 — added typed Core-client integration tests for the two new wire commands and local rejection of invalid lease identifiers/generations.
- Updated router port provenance: the original PersonaMonkey `routerd.py` blob remains recorded, while P017 adaptation commits are explicitly listed. Other imported native blobs remain exact upstream copies.

The legacy `ExitForwarder`, legacy authenticator, and legacy `prepare_exit` / `release_exit` section were compared against P016 `main` and are byte-for-byte unchanged.

## CI evidence

P017 is deterministic and credential-free. Tests use local TCP/Unix-socket fixtures and synthetic relay behavior; they do not use real Mullvad configuration, WireGuard private material, Perchance sessions, browser profiles or MCP.

The local Chromium listener is intentionally unauthenticated because Chromium cannot provide the legacy SOCKS credential path. Its protections in V1 are loopback-only binding plus short, route/generation-scoped lifetime. This does not claim protection from malicious processes running as the same Linux user.

## Deviations / ADRs

## Known issues / unknowns

- P017 does not launch Chromium through the new forwarder or prove browser egress. P018 owns synthetic protected launch and independent egress verification.
- P017 does not establish DNS/QUIC/WebRTC leak resistance or route-loss behavior; P019 owns those properties.
- Real Mullvad interoperability remains P048–P049 live acceptance.
- Lease IDs/generations are ownership-correlation values, not secrets, and loopback is not a same-user security boundary.
