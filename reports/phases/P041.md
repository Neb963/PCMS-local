## Objective

Add read-only Statistics and a coherent integrity-checked Core/module backup that excludes Persona browser profiles by default.

## Implemented

- T041.1 — added `OperationalStatistics`, which opens the PCMS SQLite database read-only and exposes only aggregate operation facts (state, operation kind, owner kind, terminal/unresolved counts and time bounds). It exposes no authoritative mutation handle and reads no durable secret payloads.
- T041.2 — added coherent SQLite backup through Node's supported SQLite backup API; the completed snapshot determines the exact module versions referenced by `module_state_generations`, and the backup copies only their immutable `.pcmsmod` artifacts. The v1 manifest records application/schema identity, migration-history SHA-256, module manifests/digests and per-file size/SHA-256. Validation runs SQLite `quick_check`, verifies DB identity/history, exact module references, package identity/manifests, filesystem membership and every file hash. Snapshot journal mode is normalized to DELETE so the published backup is self-contained rather than depending on WAL sidecars.
- T041.3 — added automatic Core-backup retention with a bounded 1–365 retention count (default 7). Retention only deletes directories with the strict managed backup ID form and a valid Core-backup manifest, always protects the just-created backup, and ignores unrelated operator content. The Core-backup manifest explicitly records `profiles.included: false`; browser Persona profile files are never traversed or copied.
