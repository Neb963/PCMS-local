## Objective

Create stable Generator identity independent of mutable slug and validate Account/Generator imports atomically.

## Implemented

- T022.1 — appended immutable migration `0008-generator-identity` with a stable `generator_local_id` primary key, owning Account foreign key, mutable current slug, optional stable provider ID, revision/timestamp state, a partial unique provider-ID index when the provider ID is known, and lookup indexes that do not treat slug as identity.
- T022.1 — added Core-owned `GeneratorRepository` creation/read inventory behavior with normalized slug/provider metadata, safe local IDs, Account ownership validation and typed uniqueness failures. Multiple managed Generators may carry the same mutable slug; local identity remains distinct.
- T022.2 — added expected-revision-fenced `updateIdentity` for provider ID/current-slug observations. Updates preserve `generator_local_id` and Account ownership, are idempotent when metadata is unchanged, increment revision only on real change and leave the row unchanged on stale revision or provider-ID collision.
- T022.3 — added reusable pure Account/Generator input preparation plus `InventoryImportService.importBatch`. The complete batch is normalized and checked for duplicate Account IDs, Generator local IDs, known provider IDs, existing-identity collisions and missing Account ownership before any write begins.
- T022.3 — after preflight, import takes one `BEGIN IMMEDIATE` write transaction, revalidates database compatibility under the lock, inserts Accounts before Generators and commits only after the whole batch succeeds. Any apply-time failure rolls the entire batch back.
- T022.3 — import may attach an imported Generator to either an Account in the same batch or a pre-existing Account; it does not update existing entities implicitly.

## Deviations / ADRs

No ADR change was required.

The mutable provider slug is intentionally indexed only for lookup and is not unique or authoritative identity. The stable local Generator ID is always authoritative inside PCMS-local; a provider stable ID is additionally unique only when known. This follows GEN-02 without assuming that mutable provider names are durable identifiers.

Import is create-only in P022. Existing Account/Generator identity collisions fail the whole batch rather than becoming implicit updates or merges. That keeps import semantics explicit and prevents ambiguous identity reconciliation from being smuggled into a foundation phase.
