## Objective

Preserve the proven PersonaMonkey native-router baseline exactly while adding a bounded typed Unix-socket client that Core can use without acquiring root or `CAP_NET_ADMIN`.

## Implemented

- T016.1 — re-ran the exact imported-port verification and native hardening suite before adapting any PCMS-local routing code. The pinned PersonaMonkey router daemon, sanitizer, systemd unit, diagnostic client and imported tests remained byte-for-byte at their recorded provenance blobs.
- T016.2 — added `src/routing/native-router-client.ts`, a Core-side Unix-domain-socket client with a fixed baseline command surface (`ping`, `status`, `list_entries`, `ensure_up`, `stop`, `restart`, `set_entry`), bounded request/response sizes, a total operation timeout, request correlation IDs, strict response validation and typed transport/protocol/daemon-rejection errors. Wire-format snake_case is converted to typed Core-facing fields.
- T016.2 — added real local Unix-socket integration coverage for supported commands, daemon rejection, unavailable sockets, correlation mismatch, oversized responses, timeout, invalid configuration and invalid entry input. The P016 client intentionally exposes no `prepare_exit` method.
- T016.3 — added Linux integration evidence that the Core Node process in GitHub Actions is non-root, has no effective `CAP_NET_ADMIN` bit in `/proc/self/status`, and can still use the typed router client over a user-owned mode-`0600` Unix socket.

No imported `native/` file was modified. Firefox-compatible `prepare_exit` semantics and Chromium routed launch/forwarder behavior remain unchanged.

- Protected Chromium launch, synthetic egress verification, leak resistance and route switching remain P017–P020 scope.
