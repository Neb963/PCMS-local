## Objective

Establish pcmsd configuration/data-root resolution, loopback startup and single-instance ownership with minimal health/readiness, without adding SQLite migrations, Web UI or CLI feature surfaces.

## Implemented

- T002.1 — implemented XDG-aware config/data/cache roots with safe explicit `PCMS_*_ROOT` overrides, normalized absolute-path validation, filesystem-root rejection, deterministic runtime/config paths and private `0700` directory creation.
- T002.2 — implemented atomic single-instance ownership using exclusive `wx` lock creation, `0600` owner records, PID plus Linux process-start identity to detect PID reuse, stale-owner reclamation, fresh incomplete-lock refusal and token-checked release.
- T002.3 — implemented IPv4 loopback-only pcmsd startup with minimal `/api/v1/health`, `/api/v1/ready` and `/api/v1/version` endpoints, configured port validation, structured foreground startup/shutdown messages, SIGINT/SIGTERM close handling, bind-failure cleanup and restart coverage.

No SQLite database/migrations, Web UI, CLI feature surface, browser management, provider behavior or routing adaptation was added.

## Deviations / ADRs

No architecture deviation. The implementation follows ADR-001 and architecture startup/installation/security contracts: pcmsd is an unprivileged local service and its bootstrap HTTP surface binds IPv4 loopback only.

The bootstrap port defaults to `17380` and can be overridden through validated `PCMS_PORT`. Programmatic `startPcmsd({ port: 0 })` is intentionally allowed only as an integration-test/runtime API convenience for ephemeral test binding.
