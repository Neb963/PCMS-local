## Objective

Prove that a generic external DevTools client can discover and attach to an already-running PCMS-owned Chromium Persona, interact through CDP, detach, and leave the Persona browser/profile/process intact.

## Implemented

- T015.1 — added `ChromiumBrowserManager.resolveDevToolsEndpoint(personaUid)` as the controlled Core-level endpoint discovery surface. It first reconciles the Persona, then revalidates complete persisted runtime evidence, the Linux process fingerprint/profile ownership, and the profile-scoped `DevToolsActivePort` against the persisted port/path before returning the loopback-only endpoint. A gone process is reconciled closed; mismatched/incomplete ownership or an unavailable expected endpoint fails closed as ownership ambiguity instead of exposing a stale port.
- T015.2 — added `tests/browser/chromium-devtools-attach.test.mjs`, which uses Node's generic WebSocket client directly against the real browser-level CDP endpoint. The test creates a target, attaches with flattened CDP sessions, evaluates JavaScript, detaches the target session, closes the temporary target, and disconnects the client. No MCP, Puppeteer, provider credential, or new dependency is used.
- T015.3 — the same real-Chromium acceptance captures the running runtime record and profile directory before attachment, then after client disconnect proves the Persona remains OPEN, the profile directory still exists, the persisted PID/DevTools evidence is unchanged, endpoint ownership can be freshly revalidated, `/json/version` remains healthy, and a second independent generic CDP connection can call `Browser.getVersion`. Browser shutdown remains an explicit PCMS session action.

No routing, provider automation, local HTTP API exposure, or MCP interoperability was implemented.
