## Objective

Make the foundation start, stop, restart and package without requiring end-user npm/pnpm commands, while stopping short of the final installer/release-hardening work.

## Implemented

- T005.1 — added a user-systemd service template that delegates to the same foreground pcmsd entrypoint, uses a private `0077` umask, bounded `on-failure` restart policy, explicit optional environment file, graceful SIGTERM and a finite stop timeout. Added authenticated `/api/v1/diagnostics` and `pcms diagnostics [--json]` through the same typed Core API; diagnostics expose safe local runtime/path/database/API state without returning the bearer token.
- T005.2 — added a Linux development/release bundle skeleton under `build/pcms-local-dev` containing the pinned Node executable, compiled application, direct `pcmsd`/`pcms` shell launchers, user-systemd unit, bundle manifest and deterministic SHA-256 inventory. Bundle smoke verifies executable/file layout, pinned runtime identity, checksums and that launchers contain no npm/pnpm/yarn/node_modules dependency. Packaging CI now validates both npm package surface and the self-contained bundle surface.
- T005.3 — added real-process lifecycle acceptance. Integration builds the bundle, removes useful package-manager lookup from `PATH`, launches the bundled pcmsd, exercises bundled diagnostics, sends SIGTERM, proves clean exit and instance-lock removal, then restarts on the same config/data roots and proves the per-install API token and SQLite migration record are unchanged. The restarted bundled CLI again reaches the same Core API successfully.

No final installer, desktop entry, SBOM/reproducibility release matrix, signed release artifact, module-runner, .pcmsmod format or P006 module behavior was added.

## Deviations / ADRs

No architecture deviation. The phase follows architecture 13 by retaining manual foreground execution for development while providing the user-systemd service shape, and by carrying a pinned Node runtime so the runtime bundle does not depend on end-user npm/pnpm commands.

The bundle is deliberately a skeleton rather than the final installer. It currently contains only components implemented through P005; later module-runner/default modules, desktop integration, install/update metadata, SBOM/reproducibility and final installer behavior remain owned by their later phases.

## Known issues / unknowns

- CI statically validates the user-systemd unit but does not start it under an actual logged-in systemd user manager. The delegated foreground process lifecycle is exercised directly and deterministically.
- The bundle is Linux-only and currently copies the exact Node executable from the pinned build environment; final distribution provenance/reproducibility/hardening belongs to M11.
- The service template targets the eventual user install root `~/.local/lib/pcms-local/current`; P005 does not add a final installer that populates or atomically switches that location.
- P006 owns the .pcmsmod manifest/archive authority and safe package parser. No module package behavior was pulled forward.
