## Objective

Exercise the dominant local crash, resource-pressure and scale failure domains and prove that unrelated work remains bounded and recoverable without depending on real provider or VPN availability.

## Implemented

- T045.1 — added adversarial process-loss matrices across Core, module and browser boundaries. The pcmsd matrix runs the actual daemon as a child process, persists PREPARED/RUNNING/VERIFYING/UNCERTAIN/SUCCEEDED operations, sends SIGKILL, restarts pcmsd and verifies only dispatched nonterminal states become UNCERTAIN while durable target claims remain intact. The module matrix crashes a real module-runner, updates and disables the module while preserving unresolved evidence, and proves unrelated Core mutations still complete. The real-Chromium matrix SIGKILLs one of two running Personas, verifies the unrelated Persona remains healthy, then safely reopens the crashed Persona.
- T045.2 — added deterministic SQLite busy and full-database fault injection, corrupt-backup validation, and a hung/poison module plus queue-flood matrix. The queue matrix exposed a real starvation gap: lower-priority work could consume every queue slot before RECOVERY/INTERACTIVE work arrived. `BoundedWorkQueue` now reserves admission capacity for recovery/control work while preserving existing priority/fairness semantics. Busy/full failures remain bounded, corrupt backups fail with structured evidence, and a timed-out module cannot make pcmsd health or reserved control lanes unavailable.
- T045.3 — extended 50+ Persona acceptance with structural disk bounds and a real-browser active-subset matrix. Sixty-four dormant Persona profiles remain marker-only and unchanged through daemon startup/query work; a separate real Chromium test keeps 60 Personas dormant while exactly two active Personas run under a configured cap and rejects a third without disturbing the two healthy sessions.

## CI evidence

Failures found during P045 were investigated and corrected rather than bypassed:

- The first T045.2 integration run (#708) failed before executing the pressure cases because a test regex contained an unescaped slash in `interactive/recovery`. The assertion syntax was corrected; no production behavior was changed for that failure.
- The queue-flood analysis identified a real admission flaw before closure: priority affected claim order but did not protect capacity from lower-priority saturation. The production queue now reserves capacity for RECOVERY and INTERACTIVE lanes, and the adversarial test proves the reservation under a full lower-priority flood.
- No live Perchance, Mullvad or MCP dependency was used.

## Deviations / ADRs

No new architecture or ADR was required. The queue admission reserve is a direct hardening of the existing bounded priority queue contract in architecture 09/14: recovery/control work must remain available under lower-priority pressure.

The scale checks deliberately use structural bounds (file/byte counts, runtime-row counts and configured browser caps) instead of wall-clock performance thresholds, avoiding runner-speed-dependent acceptance.

## Known issues / unknowns

P045 does not claim operating-system-wide disk exhaustion behavior for every filesystem call. It deterministically exercises SQLite's full-database failure path and verifies PCMS backup corruption handling; broader release artifact/security and restore drills remain P046.

Real provider/VPN failure behavior remains outside this phase by design. P048–P049 remain the only live-system acceptance phases.
